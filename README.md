# dawneast / portfolio

Ruby 백엔드와 HTML 프론트엔드로 만든 개인 포트폴리오

프로젝트와 공개 자료는 방문자가 볼 수 있고, 로그인한 관리자만 내용을 수정하거나 파일을 업로드할 수 있습니다. 흰 배경, 남색 텍스트, 파란 포인트로 구성한 반응형 화면이며 React나 Node 빌드 과정은 없습니다.

> 현재 산출물은 소스 프로젝트입니다. 외부 서버 배포나 도메인 연결은 수행하지 않았습니다. 로컬 실행과 공개 배포용 실행 경로를 분리했습니다. 검증 범위와 실행 환경 차이는 `docs/verification.md`를 확인하세요.

## 1. 바로 실행하기

Ruby 3.3 또는 3.4 환경에서 실행하세요. 이 프로젝트는 Ruby 4.x 호환성을 검증하지 않았습니다. 운영 환경에서는 선택한 Ruby 버전의 최신 보안 패치를 사용하세요.

압축을 풀고 프로젝트 폴더로 이동한 뒤:

```bash
cd dawneast-portfolio
ruby -v
gem install webrick -v "~> 1.9"
ruby bin/setup --demo
ruby app.rb
```

`bin/setup`에서 관리자 아이디와 15자 이상의 비밀번호를 입력합니다. 아이디의 기본값은 `admin`이지만 **기본 비밀번호는 없습니다**. 비밀번호 입력은 터미널에 표시되지 않습니다. 자동으로 만들어진 계정이나 공용 로그인 정보도 포함하지 않습니다.

사이트 주소: `http://localhost:4567`

관리 화면: `http://localhost:4567/admin`

종료: 실행 중인 터미널에서 `Ctrl+C`

`.html.erb` 파일을 더블클릭하거나 VS Code Live Server로 여는 방식이 아닙니다. Ruby 서버가 HTML을 생성하므로 위 명령으로 실행해야 로그인·저장·업로드가 동작합니다.

샘플 없이 빈 포트폴리오로 시작하려면 `ruby bin/setup`을 사용하세요. `--demo`는 프로젝트 3개와 첨부 노트 2개를 추가합니다. 샘플은 모두 표시를 붙여 두었으며 실제 경력이나 검증된 작업 결과가 아닙니다.

이미 계정을 만든 상태에서 setup을 다시 실행해도 기존 비밀번호는 덮어쓰지 않습니다. 분실한 비밀번호는 서버에 접근할 수 있는 운영자가 다음 명령으로 재설정할 수 있습니다.

```bash
ruby bin/setup --reset-password
```

웹 화면에서도 `관리자 → 계정 보안`에서 현재 비밀번호를 확인한 뒤 변경할 수 있습니다. 변경하면 다른 기기의 관리자 로그인도 무효화됩니다.

## 2. 들어 있는 기능

| 영역 | 기능 |
| --- | --- |
| 공개 홈 | 소개 문구, 대표 프로젝트 우선 표시, 공개 자료, 연락하기 |
| 프로젝트 | 목록·상세, 제목/소개/태그 검색, 카테고리·태그 필터 |
| 관리자 | 로그인·로그아웃, 대시보드, 비밀번호 변경 |
| 프로젝트 편집 | 추가·수정·삭제, 공개/비공개, 대표 지정, 기술 태그, 소스·사이트 링크 |
| 파일 | 드래그 앤 드롭 또는 선택, 프로젝트 연결, 공개/비공개, 다운로드·삭제 |
| 대표 이미지 | 프로젝트에 연결된 PNG/JPG/WEBP 파일을 대표 이미지로 지정 |
| 프로필 | 이름, 역할, 메인 문구, 소개, 기술, 위치, 이메일, GitHub·블로그 링크 |
| 이력서 | 공개 PDF를 이력서로 지정하고 소개 페이지에서 다운로드 |
| 문의 | 방문자 메시지를 관리자 문의함에 저장, 읽음 처리·삭제, 이메일 앱으로 답장 |
| 편의 기능 | 모바일 메뉴, 오류 안내, 빈 화면 안내, 샘플 자료 일괄 삭제 |

문의는 **사이트 내부 저장 방식**입니다. SMTP·메일 자동 발송·Discord 알림은 연결하지 않았습니다. ‘이메일로 답장’은 운영자의 이메일 프로그램을 여는 기능입니다.

프로젝트 본문은 일반 텍스트입니다. 줄바꿈은 반영되며, 입력한 HTML은 실행되지 않고 문자로 보입니다. Markdown 편집기나 HTML 실행 기능은 없습니다.

## 3. 실제 내용을 넣는 순서

먼저 관리자에 로그인하고 `프로필`에서 이름과 메인 문구, 소개, 링크를 바꾸세요. 메인 문구에 줄바꿈을 넣으면 홈 화면에도 반영됩니다. 이름과 메인 문구 외에는 비워 둘 수 있는 항목이 있습니다.

`프로젝트 → 새 프로젝트`에서 이름과 한 줄 소개를 입력하고 저장하세요. 아직 작성 중인 프로젝트는 비공개로 두고, 완성되면 공개 상태로 바꾸면 됩니다. 대표 프로젝트로 지정한 공개 항목은 홈에 먼저 표시됩니다.

프로젝트를 저장한 뒤 `파일 업로드`를 누르면 해당 프로젝트가 선택된 파일 관리 화면으로 이동합니다. 파일을 선택하고 자료 이름을 입력한 다음 공개 여부를 정해 업로드하세요. 자료 이름을 비우면 원래 파일 이름이 사용됩니다.

이미지는 파일 목록의 `대표 이미지로 설정` 버튼 또는 프로젝트 편집 화면에서 지정합니다. 방문자에게도 보이게 하려면 **프로젝트와 이미지 모두 공개 상태**여야 합니다. 공개하지 않은 대표 이미지 대신 기본 프로젝트 화면이 표시됩니다.

이력서는 프로젝트를 연결하지 않은 공통 자료로 PDF를 공개 업로드한 뒤 `프로필 → 이력서 PDF`에서 선택하면 됩니다.

### 파일 제한과 공개 규칙

허용 확장자: `PDF, PNG, JPG, JPEG, WEBP, TXT, MD, ZIP`

기본 제한: 파일 하나당 **10 MiB**, 전체 첨부파일 **500 MiB**, 한 번에 한 파일

TXT와 MD는 UTF-8 텍스트를 사용하세요. 이름은 한글을 지원하며, 저장할 때는 원본 이름 대신 무작위 식별자를 사용합니다.

파일 업로드 기본값은 비공개입니다. ‘방문자에게 공개’를 선택해도 연결된 프로젝트가 비공개라면 목록·다운로드·이미지 미리보기 모두 방문자에게 숨겨집니다. 관리자는 로그인 상태에서 확인할 수 있습니다. 이미 다른 사람이 내려받은 사본까지 회수하는 기능은 아닙니다.

프로젝트를 삭제하면 그 프로젝트에 연결된 첨부파일도 삭제됩니다. 파일만 삭제할 수도 있습니다. 샘플 일괄 삭제는 **샘플 프로젝트와 그 프로젝트에 연결된 파일, 샘플 표시가 남은 파일**을 삭제하므로 실제 자료를 연결하기 전 정리하는 것을 권합니다. 샘플 프로젝트를 수정해 저장하면 그 프로젝트의 샘플 표시는 해제되지만 기존 샘플 첨부파일의 표시는 별도로 남습니다.

ZIP을 해제하거나 업로드 파일을 서버에서 실행하지 않습니다. PDF와 텍스트는 다운로드로 전달하고, 이미지 파일만 미리보기에 사용합니다.

## 4. 폴더 구조

```text
dawneast-portfolio/
├── app.rb                    로컬 개발 서버 진입점
├── config.ru                 Rack/Puma 진입점
├── Gemfile                   의존성 및 버전 범위
├── .env.example              설정 예시
├── bin/
│   ├── setup                 관리자 생성·재설정·샘플 생성
│   └── test                  테스트 실행
├── config/puma.rb            공개 배포용 단일 프로세스 설정
├── lib/portfolio/
│   ├── config.rb             환경 설정
│   ├── http_app.rb           요청 처리, 라우팅, 권한 검사
│   ├── rack_app.rb           Rack 요청·응답 어댑터
│   ├── repository.rb         프로젝트·파일·프로필·문의 처리
│   ├── store.rb              PStore 저장
│   ├── security.rb           비밀번호·세션·요청 횟수 제한
│   ├── uploads.rb            파일 검증
│   └── view.rb               HTML 렌더링과 출력 이스케이프
├── views/
│   ├── *.html.erb            공개 페이지
│   └── admin/*.html.erb      관리자 페이지
├── public/assets/
│   ├── site.css              디자인·모바일 레이아웃
│   ├── app.js                메뉴·드래그 앤 드롭·삭제 확인
│   └── favicon.svg           기본 아이콘
├── storage/
│   ├── portfolio.pstore      실행 후 생성되는 비공개 데이터
│   └── uploads/*.blob        실행 후 생성되는 첨부파일
├── test/                     저장·권한·HTTP·Rack·설정 테스트
└── docs/
    ├── verification.md       실제 검증 결과와 미검증 항목
    └── deployment.md         공개 배포 전 확인 사항
```

소개와 프로젝트 내용은 관리자 화면에서 바꿀 수 있습니다. 화면 자체의 구조를 바꾸려면 `views/`, 색상·간격·폰트 크기는 `public/assets/site.css`, 요청 처리나 업로드 정책은 `lib/portfolio/`를 수정하세요.

HTML은 Ruby ERB 템플릿에서 렌더링합니다. 프론트엔드 패키지 설치, React, npm 빌드, 외부 CDN은 필요하지 않습니다. 폰트 파일은 포함하지 않으며 운영체제에 설치된 글꼴을 사용합니다.

## 5. 설정 변경

기본값으로 실행할 때 `.env` 파일은 필요 없습니다. 변경할 때만 복사하세요.

```bash
cp .env.example .env
```

```dotenv
APP_ENV=development
BIND=127.0.0.1
PORT=4567
APP_URL=http://localhost:4567
STORAGE_DIR=storage
MAX_UPLOAD_MB=10
MAX_STORAGE_MB=500
```

포트를 바꾸면 `PORT`와 `APP_URL`을 함께 수정하세요. `STORAGE_DIR`은 `public/` 밖에 있어야 합니다. 설정 파일을 수정한 뒤 서버를 재시작하면 적용됩니다. 운영체제에 이미 설정된 환경변수가 `.env`보다 우선합니다.

`MAX_UPLOAD_MB`와 `MAX_STORAGE_MB`의 MB는 이 프로젝트에서 1,048,576바이트 단위로 처리합니다. 업로드 제한은 1~100, 전체 파일 제한은 1~100000 범위입니다. 실제 서버 디스크 용량보다 크게 설정하지 마세요. 전체 파일 제한은 첨부파일 합계만 계산하며 데이터 저장 파일·로그·백업 용량은 별도입니다.

`.env`는 단순한 `KEY=value` 형식입니다. 변수 치환, 셸 명령, 값 뒤의 인라인 주석은 지원하지 않습니다.

## 6. 테스트

Minitest가 설치되어 있지 않다면:

```bash
gem install minitest -v "~> 5.20"
```

테스트 실행:

```bash
ruby bin/test
```

테스트는 매번 임시 폴더와 테스트용 계정을 생성하고 종료 시 정리합니다. 실제 `storage/`의 프로젝트나 비밀번호를 수정하지 않습니다. 테스트 파일의 고정 비밀번호 문자열은 테스트 픽스처이며, 실제 관리자 계정의 기본값이 아닙니다.

HTTP 오류의 서버 스택을 확인하려면 Linux/WSL에서 다음과 같이 실행할 수 있습니다.

```bash
TEST_DEBUG=1 ruby bin/test
```

`Gemfile` 전체를 설치한 환경에서는 `bundle exec ruby bin/test`로도 실행할 수 있습니다. 생성된 `Gemfile.lock`을 배포에 사용하면 배포 환경의 의존성을 고정할 수 있습니다. 이 산출물에는 검증하지 않은 lockfile을 임의로 만들지 않았습니다.

## 7. 저장과 백업

데이터는 Ruby PStore 파일에, 첨부파일 원본은 `storage/uploads/`에 저장됩니다. 별도 데이터베이스 서버는 필요 없습니다. 이 구성은 단일 운영자·단일 애플리케이션 프로세스를 기준으로 만들었습니다.

**서버를 종료한 상태에서 `storage/` 전체를 함께 백업**하세요. 메타데이터 파일만 백업하거나 첨부파일만 백업하면 자료 연결이 복구되지 않을 수 있습니다. `STORAGE_DIR`을 변경했다면 그 경로를 백업해야 합니다.

저장 파일에는 비밀번호 해시와 비공개 문의 내용이 들어 있습니다. GitHub에 올리거나 정적 웹서버로 공개하지 마세요. 다른 사람이 전달한 PStore 파일을 열거나 복원하지 말고 본인이 생성한 신뢰할 수 있는 백업만 사용하세요.

로그인 세션은 메모리에 있어 서버 재시작 시 해제됩니다. 계정·프로필·프로젝트·첨부파일·문의는 저장 파일에 남습니다.

## 8. 보안과 운영 범위

업로드 권한, 공개 여부, CSRF 토큰, Host/Origin, 크기, 허용 확장자, 기본 파일 시그니처를 서버에서 검사합니다. 비밀번호는 평문이 아닌 PBKDF2-HMAC-SHA256 해시로 저장하고 로그인 시 세션을 교체합니다. CSP, HttpOnly/SameSite 쿠키, 다운로드의 `nosniff`와 attachment 처리를 적용했습니다.

이는 **완전한 보안 감사나 악성 파일 검사 완료를 의미하지 않습니다**. 기본 시그니처 검사는 파일의 모든 구조를 검증하지 않습니다. 특히 PDF·ZIP 내부의 위험한 내용이나 악성코드를 검사하지 않습니다. 공개할 파일은 운영자가 검토해야 합니다.

로그인은 IP당 15분에 5회, 문의는 IP당 10분에 3회로 제한합니다. 제한과 세션은 프로세스 메모리에 저장됩니다. 프록시 뒤에서는 같은 IP로 인식될 수 있으므로 공개 배포 시 프록시의 요청 횟수 제한과 함께 조정해야 합니다. 임의의 X-Forwarded-For 헤더를 신뢰하지 않습니다.

문의 수집 안내는 기본 문구입니다. 실제 공개 전 운영자의 연락처, 보관·삭제 정책, 필요한 개인정보 안내를 운영 상황에 맞게 정리하세요. 메시지는 자동 만료·자동 삭제되지 않습니다.

**`ruby app.rb`는 로컬 개발 전용입니다. 공개 배포에는 `config.ru`와 Puma를 사용하세요.** 배포 서버·HTTPS·도메인 설정과 그 환경에서의 재검증은 `docs/deployment.md`에 정리했습니다.
