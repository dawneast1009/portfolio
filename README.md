# 나의 포트폴리오 · 학교 제출용

Ruby 백엔드 + HTML/ERB 화면. 왼쪽 목차와 글·첨부파일 중심의 작은 포트폴리오입니다.

> 이 ZIP은 수정된 소스입니다. 사용자의 GitHub 저장소에 push하거나 외부 서비스를 배포한 상태는 아닙니다. 저장한 실제 활동·파일·비밀번호도 포함하지 않습니다.

## 1. 메뉴

| 페이지 | 내용 |
| --- | --- |
| 홈 | 짧은 소개, 각 페이지 바로가기, 포트폴리오 안내 기록 |
| 내 소개 | 강점, 흥미, 가치관, 진로활동 요약 |
| 진로활동 | 관심 분야, 관심 직업, 관심 학과 |
| 주요 활동 및 스킬 | 교과활동, 동아리활동, 진로활동, 사용 프로그램 및 숙련도, 기타 강점 |
| 프로젝트 | 독서, 주제탐구보고서, 교과·진로·개인 프로젝트, 작품 및 결과물 |

컴퓨터에서 작성하는 것을 기준으로 만들었으며 작은 화면에서도 글쓰기·파일 첨부와 열람을 지원합니다. 노션처럼 글과 파일을 정리하는 방식이지, 노션의 자유 블록 편집·실시간 공동편집·자동 저장 기능을 구현한 것은 아닙니다.

## 2. 컴퓨터에서 실행

Ruby 3.3 또는 3.4의 보안 업데이트가 적용된 버전을 준비하세요. 공개 배포용 Ruby 버전은 `.ruby-version`을 따릅니다.

```bash
cd dawneast-portfolio
gem install webrick -v "~> 1.9"
ruby bin/setup
ruby app.rb
```

설정에서 관리자 아이디와 15자 이상의 비밀번호를 입력합니다. 고정된 기본 비밀번호는 없습니다.

```text
사이트: http://localhost:4567
관리자: http://localhost:4567/admin
종료: Ctrl+C
```

HTML 파일을 더블클릭하는 것이 아니라 Ruby 서버를 실행해야 편집·로그인·파일 업로드가 동작합니다. `.env`는 꼭 만들 필요가 없습니다. 설정을 바꿀 때 `.env.example`을 복사해 사용합니다.

예전 `--demo` 옵션은 기존 샘플과 테스트의 호환성을 위해 남겨 두었습니다. 새 학교 포트폴리오를 작성할 때는 위와 같이 옵션 없이 시작하세요. 제공한 화면 캡처에는 테스트를 위해 별도로 만든 ‘예시’ 기록이 보이지만 실제 저장 데이터는 이 ZIP에 없습니다.

## 3. 글 쓰고 파일 붙이기

작성자 로그인 → 페이지 선택 → 항목 옆 ‘기록 추가’ → 제목·내용 입력 → ‘기록 저장’ → 아래 첨부파일 영역에서 파일 선택 → ‘파일 첨부’

기록의 공개 상태는 처음에 비공개입니다. 기록을 공개하고 첨부파일에서도 ‘이 파일을 방문자에게 공개’를 선택해야 방문자가 볼 수 있습니다. 파일을 여러 개 붙일 수 있지만 한 번에 하나씩 업로드합니다. 이미지는 기록 상세 페이지에서 미리보기로도 표시합니다.

본문은 일반 텍스트와 줄바꿈입니다. HTML은 실행하지 않습니다. 관련 링크 한 개를 넣을 수 있고 숙련도는 입문/활용/능숙 중 선택합니다. 숙련도는 자기평가로 표시됩니다. 수정 후에는 저장 버튼을 눌러야 합니다.

### 목차 편집

작성자로 로그인한 뒤 홈의 `목차 편집` 또는 왼쪽 메뉴 아래의 `목차 편집`을 누릅니다. 이 화면에서 `내 소개`, `진로활동` 같은 상위 메뉴와 `강점`, `흥미` 같은 하위 항목을 추가하거나 이름과 순서를 바꿀 수 있습니다. 상위 메뉴의 설명과 아이콘도 함께 수정할 수 있습니다.

이름을 바꿔도 내부 주소와 기존 기록 연결은 유지됩니다. 기록이 들어 있는 메뉴나 항목은 실수로 자료가 사라지지 않도록 삭제가 차단됩니다. 하위 항목은 기록을 다른 항목으로 옮기거나 삭제한 뒤 지울 수 있고, 상위 메뉴는 안의 기록을 모두 삭제한 뒤 지울 수 있습니다. 홈 메뉴는 수정할 수 있지만 삭제하거나 다른 위치로 이동할 수 없습니다.

목차 설정은 글과 파일처럼 `storage/portfolio.pstore`에 저장됩니다. 무료 Render가 재시작되거나 재배포되면 수정한 목차도 초기화될 수 있으므로 중요한 구성과 자료는 제출용 ZIP 및 `storage/` 백업으로 보관하세요.

기록 또는 첨부파일을 삭제하면 복구되지 않습니다. 기록을 삭제할 때에는 연결된 파일도 함께 삭제합니다. 실제 이름·학교·학번·연락처 등 개인정보는 공개 범위를 확인하고 필요한 내용만 쓰세요.

### 파일 형식

- PDF, PNG, JPG/JPEG, WEBP, TXT, MD, ZIP
- HWP, HWPX, DOCX, PPTX, XLSX
- 파일 하나당 기본 10 MiB, 로컬 전체 기본 500 MiB, 무료 Render 설정은 전체 100 MiB

문서는 다운로드로 제공합니다. ZIP을 해제하거나 첨부 문서를 서버에서 실행하지 않습니다. 확장자와 기본 파일 시그니처를 검사하지만 바이러스 검사나 문서 전체 구조 검증은 아닙니다. 공개할 자료는 작성자가 확인하세요. 옛 DOC/PPT/XLS 및 매크로 형식은 허용하지 않습니다.

## 4. 무료 최종 제출: HTML 제출본 + GitHub Pages

**작성·파일 업로드는 Ruby 사이트에서, 최종 공유는 내보낸 HTML 사이트로 합니다.**

1. 작성자 메뉴의 ‘공유 및 제출’에서 ‘제출용 사이트 ZIP 받기’를 누릅니다.
2. ZIP을 풀고 `index.html`을 열어 공개할 기록과 파일이 있는지 확인합니다.
3. 별도의 공개 GitHub 저장소(예: `portfolio-submission`)를 만듭니다. 작성용 Ruby 소스 저장소를 강제로 공개로 바꿀 필요는 없습니다.
4. ZIP 자체가 아니라 압축을 푼 폴더 안의 내용 전체를 저장소 첫 화면에 올립니다. 여기에는 `index.html`, 기본 페이지 HTML, 목차에서 추가한 `page-*.html`, 기록별 HTML, `assets/`, `files/`, `.nojekyll`이 포함됩니다.
5. 저장소 `Settings → Pages → Source: Deploy from a branch → main / (root) → Save`를 선택합니다.
6. 배포가 끝난 뒤 Pages 화면에 표시되는 실제 주소를 열어 확인하고 제출합니다.

GitHub Free의 Pages는 공개 저장소를 사용합니다. 소스·비밀번호·storage 폴더가 아니라 **내보낸 공개 제출본만** 올리세요. 사이트도 공개되므로 타인 개인정보가 있는 자료는 넣지 마세요. GitHub 사용 정책과 제공 한도 내에서 사용해야 합니다.

내보내기는 공개된 페이지·기록·첨부파일만 포함합니다. 관리자 계정, 비밀번호, 세션, 문의함, 비공개 자료는 포함하지 않습니다. 첨부파일 이름이 같아도 내부 저장 경로를 분리합니다. 내보내기 전체 제한은 64 MiB입니다. 제출본은 읽기 전용이며 수정·파일 업로드 기능이 없습니다. 내용을 바꾸려면 Ruby 원본에서 수정 후 새 제출본으로 갱신합니다.

명령어로도 내보낼 수 있습니다.

```bash
ruby bin/export
# 기존 submission 폴더가 있을 때는 새로운 폴더 이름 사용
ruby bin/export submission-new
```

기존 출력 폴더를 자동 삭제하거나 덮어쓰지 않습니다. 공유 링크 복사는 실제 주소를 복사할 뿐 새로운 서버나 도메인을 생성하지 않습니다. localhost, 127.0.0.1, file:// 주소는 제출 주소로 사용할 수 없습니다.

## 5. 이미 GitHub·Render에 올린 사이트 업데이트

서버를 사용 중이면 먼저 기존 `storage/` 전체를 서버가 정지한 상태에서 안전하게 백업하세요. 무료 Render에만 저장한 자료는 사라질 수 있으므로 중요한 파일 원본은 컴퓨터에 보관하세요.

이번 ZIP의 `dawneast-portfolio` 폴더 **안의 소스 파일**을 기존 저장소의 같은 위치에 갱신하고 커밋합니다. 기존 `.env`와 실제 `storage/` 데이터는 GitHub에 올리지 마세요. 새 ZIP에 실제 저장 데이터가 없으므로 로컬 기존 데이터 폴더를 삭제할 이유가 없습니다.

Git CLI를 쓰는 경우 기존 저장소를 연 상태에서 소스만 교체한 뒤:

```bash
git status --short
git add .
git diff --cached --stat
git commit -m "Simplify portfolio into five notebook pages"
git push
```

커밋 전에 `.env`, `.pstore`, `.blob`, 원본 백업, 개인정보가 들어가지 않았는지 확인하세요. 새 파일 `lib/portfolio/notebook.rb`, `notebook_routes.rb`, `static_export.rb`, `views/notebook/`, `public/assets/notebook.css`도 모두 포함해야 합니다. 일부 화면 파일만 덮어쓰면 동작하지 않습니다.

**이번 버전의 `render.yaml`과 `render-free.yaml`은 모두 Free 설정입니다. 이전 ZIP에서 render.yaml이 유료였던 것과 다릅니다.** 기본 `SEED_DEMO`는 false라 처음에는 빈 항목으로 시작합니다. 유료 디스크나 서비스는 자동 생성하지 않습니다.

Render 자동 배포가 연결돼 있으면 커밋 후 서비스의 배포 결과를 확인하세요. 새로 배포할 때에는 Blueprint에서 `render-free.yaml`을 선택하고 기존 안내대로 ADMIN_PASSWORD를 설정합니다. 배포 전 실제 화면에서 Free인지 다시 확인하세요. `APP_URL`은 Render가 할당한 HTTPS 주소를 기본으로 사용합니다.

무료 Render는 재시작·재배포·유휴 종료 때 로컬의 글과 파일을 잃습니다. 관리자에서 바꾼 내용은 GitHub에 자동 커밋되지 않습니다. 따라서 무료 Render 주소만을 장기 보관용 제출본으로 사용하는 방식은 권장하지 않습니다. 이 문제를 외부 데이터베이스로 해결한 상태도 아닙니다.

## 6. 기존 데이터 호환과 백업

PStore 형식과 계정은 유지합니다. 기존 프로젝트는 ‘프로젝트 → 개인 프로젝트’에 나타나고 기존 파일도 연결을 유지합니다. 예전 소개글과 이력서가 있으면 소개 페이지에서 표시합니다. 이전 `/admin/files`, `/admin/projects` 등 경로는 기존 데이터 관리를 위해 남겨 두었지만 새 주 메뉴에서는 보이지 않습니다.

서버를 끄고 `storage/` 전체를 함께 백업하세요. 제출용 ZIP은 편집용 백업이 아니므로 Ruby 원본 데이터 복구에 사용할 수 없습니다. 신뢰할 수 없는 PStore 파일을 불러오지 마세요. 공개 폴더 또는 GitHub에 저장 데이터를 올리지 마세요.
