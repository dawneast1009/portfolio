# 학교 포트폴리오 검증 기록

확인일: 2026-09-08

## 실행 환경

- Ruby 3.3.8
- WEBrick 1.9.1 (이 작업 환경에 사전 설치된 버전)
- Minitest 5.20.0
- Chromium / Playwright: 컨테이너에 설치된 Chromium 사용

Gemfile의 공개 배포용 조건은 그대로 유지했습니다: WEBrick >= 1.9.2, Rack >= 3.2.7, Puma >= 8.0.2. .ruby-version은 이전 패키지와 같은 3.3.12입니다. 이 환경에서 외부 gem 서버에 대한 DNS 접근이 되지 않아 의존성 설치 및 운영용 Puma 프로세스 실행은 검증하지 않았습니다. 구버전 WEBrick을 공개 배포하라는 뜻이 아닙니다.

## 자동 기능 테스트

`ruby bin/test -v`

105 runs, 782 assertions, 0 failures, 0 errors, 0 skips

기존 테스트와 새 학교 포트폴리오 테스트를 함께 실행했습니다. HTTP 기능은 WEBrick의 실제 로컬 HTTP 요청과 Rack env/response 인터페이스 양쪽에서 확인합니다. 동일한 HTTP 행동 테스트가 두 어댑터에서 각각 실행되므로 테스트 개수는 고유 기능 개수와 다릅니다.

확인한 주요 동작: 5개 메뉴와 소항목, 기록 저장과 입력 검증, 기존 프로젝트 호환, 파일 업로드·다운로드, 추가 문서 확장자와 잘못된 시그니처 거절, 공개/비공개 접근, CSRF, 출력 이스케이프, 계정·세션, 내보내기 접근 권한, 공개 자료만 포함하는 ZIP, 무료 Blueprint 설정.

새 기능 테스트를 먼저 실행해 9개 도메인 테스트 및 5개 HTTP 기능 테스트의 실패를 확인하고 구현했습니다. 기존 소개 PDF 표시와 검색 필터의 회귀를 전체 테스트에서 찾아 수정했습니다. 사용자의 실제 저장소는 수정하지 않았습니다.

## 브라우저 화면 검사

공개 5페이지 × 화면 너비 360/390/768/1440px = 20개 조합
편집/공유/기본정보 3화면 × 같은 4개 너비 = 12개 조합
총 32개 조합에서 가로 넘침 없음. 모바일 목차 열기·Escape 닫기, 편집 변경 시 저장 안내 동작을 확인했습니다.

브라우저에서 로컬 네트워크 접속이 정책상 차단돼 있었으므로 정책을 변경하지 않았습니다. 로컬 HTTP로 받은 HTML과 같은 CSS/JavaScript를 Chromium 문서에 주입하는 오프라인 렌더링으로 화면을 검사했습니다. 따라서 브라우저가 직접 Ruby 서버에 폼을 제출하는 완전한 E2E 테스트는 아닙니다. 폼 저장과 업로드는 별도의 실제 HTTP 요청 테스트로 검증했습니다.

스크린샷은 임시 데이터에서 생성한 예시 화면입니다. 실제 사용자의 진로·성과를 작성한 것이 아닙니다. 기기의 실물 테스트, Safari/Firefox 검증은 하지 않았습니다.

## 내보내기

실제 로그인한 HTTP 세션으로 /admin/export.zip을 내려받았습니다. Python 표준 zipfile 모듈로 CRC 검사와 추출에 성공했고 모든 로컬 href/src 목적지 파일이 ZIP 안에 존재함을 확인했습니다. 링크는 상대 경로이므로 저장소 하위 경로를 요구하지 않습니다. 공개되지 않은 기록·파일과 관리자 정보 제외를 테스트했습니다.

## 아직 확인하지 않은 것

- 사용자의 실제 GitHub 저장소에 변경 업로드
- Render/Puma 운영 프로세스, 외부 HTTPS 및 실제 호스팅 환경
- GitHub Pages의 실제 공유 URL 생성
- 바이러스 검사, 문서 파일 전체 구조 분석, 제3자 보안 감사
- 무료 Render의 영구 저장 (지원하지 않는 구성이며 영구 저장을 구현했다고 주장하지 않음)

## 2026-09-09 목차 편집 검증

`ruby bin/test`: 122 runs, 968 assertions, 0 failures, 0 errors, 0 skips

관리자 목차 편집 기능은 저장소 계층과 실제 HTTP 요청 양쪽에서 검증했습니다. 기존 다섯 메뉴와 밑줄이 포함된 기존 하위 항목 ID를 유지하는 이전 데이터 호환, 상위 메뉴·하위 항목 추가 및 이름 변경, 순서 이동, 빈 항목 삭제, 기록이 연결된 항목의 삭제 차단, 홈 삭제 차단, 입력 길이·제어문자·아이콘·개수 제한을 확인했습니다.

관리 화면은 비로그인 접근을 로그인 화면으로 보내며 모든 변경 요청에 기존 CSRF 검사를 적용합니다. 저장한 목차가 공개 페이지, 사이드바, 홈 목록, 기록 작성 화면, 기록 상세 화면과 정적 제출용 ZIP에 같은 이름과 순서로 반영되는 것을 WEBrick 및 Rack 요청 테스트로 확인했습니다.

무료 Render의 파일 시스템 제약은 바뀌지 않습니다. 배포 환경에서 재시작 또는 재배포가 일어나면 PStore에 저장된 사용자 목차가 기존 글과 함께 초기화될 수 있습니다.
