# 편집 가능한 포트폴리오 목차 설계

## 목표

관리자가 포트폴리오의 상위 메뉴와 각 메뉴 안의 하위 항목을 화면에서 추가하고, 수정하고, 순서를 바꾸고, 삭제할 수 있게 한다. 기존 학교용 메뉴와 기록은 그대로 유지하며 공개 화면과 제출용 정적 ZIP은 저장된 목차를 사용한다.

## 사용자 흐름

- 로그인한 관리자는 홈과 사이드바의 `목차 편집` 링크로 관리 화면을 연다.
- 상위 메뉴에는 제목, 설명, 아이콘을 입력한다. 새 메뉴의 내부 ID와 URL은 서버가 자동 생성한다.
- 하위 항목에는 이름을 입력한다. 내부 ID는 서버가 자동 생성한다.
- 위·아래 버튼으로 상위 메뉴와 하위 항목의 순서를 한 단계씩 바꾼다.
- 제목이나 이름을 바꿔도 내부 ID는 바뀌지 않으므로 기존 URL과 기록 연결이 유지된다.
- 기록이 연결된 상위 메뉴나 하위 항목은 삭제할 수 없으며 화면에 이유를 표시한다.
- `홈`은 제목, 설명, 아이콘과 하위 항목을 편집할 수 있지만 상위 메뉴 자체는 삭제하거나 첫 위치에서 이동할 수 없다.
- 빈 상위 메뉴와 빈 하위 항목은 삭제할 수 있다. 상위 메뉴는 하위 항목이 남아 있어도 연결된 기록이 전혀 없으면 하위 항목과 함께 삭제한다.

## 저장 구조와 호환성

PStore 상태에 `notebook_navigation` 배열을 추가한다. 각 상위 메뉴는 `id`, `title`, `description`, `icon`, `sections`를 가지며, 각 하위 항목은 `id`, `title`을 가진다. 화면 표시 순서는 배열 순서를 따른다.

기존 고정 메뉴는 기본 목차로 옮긴다. 저장소에 `notebook_navigation`이 없는 기존 데이터는 읽을 때 기본 목차를 제공하고, 처음 목차를 변경할 때 전체 기본 목차를 저장한다. 기존 ID인 `home`, `about`, `career`, `activities`, `projects`와 기존 하위 항목 ID를 그대로 사용해 현재 기록과 `/about`, `/career`, `/activities`, `/projects` 주소를 보존한다.

새 상위 메뉴 ID는 `page-`와 무작위 12자리 16진수로 만들고, 새 하위 항목 ID는 `section-`과 무작위 12자리 16진수로 만든다. 사용자가 입력한 한글 제목을 URL이나 파일 경로로 사용하지 않는다. 새 메뉴의 공개 주소는 `/<상위 메뉴 ID>`, 정적 제출본 파일명은 `<상위 메뉴 ID>.html`이다.

삭제는 한 번의 저장 트랜잭션 안에서 현재 기록을 다시 확인한 후 처리한다. 이렇게 해서 화면을 연 뒤 다른 요청이 기록을 추가한 경우에도 자료가 사라지지 않는다. 알 수 없는 이전 기록의 기존 `projects/personal` 대체 규칙은 유지한다.

## 서버 구조

`Portfolio::Notebook`은 고정 `PAGES` 대신 기본 목차, ID 생성, 입력 검증과 조회 보조 함수를 제공한다. 실제 목차 조회와 변경은 `Portfolio::Repository`가 담당한다.

저장소에는 다음 동작을 둔다.

- 전체 목차 조회
- 상위 메뉴 추가 및 수정
- 상위 메뉴 한 단계 위·아래 이동
- 빈 상위 메뉴 삭제
- 하위 항목 추가 및 수정
- 하위 항목 한 단계 위·아래 이동
- 기록이 없는 하위 항목 삭제

제목은 1~60자, 설명은 0~300자이며 제어 문자를 허용하지 않는다. 상위 메뉴는 홈을 포함해 최대 20개, 각 메뉴의 하위 항목은 최대 30개로 제한한다. 아이콘은 애플리케이션이 지원하는 목록에서만 선택한다. 요청의 상위 메뉴 ID와 하위 항목 ID가 실제 부모·자식 관계와 일치하지 않으면 저장하지 않는다.

`NotebookRoutes`, `View`, `StaticExport`는 요청마다 저장소에서 목차를 받아 사용한다. 공개 페이지, 사이드바, 홈의 둘러보기 목록, 기록 편집기의 항목 선택, 기록의 뒤로 가기 링크와 정적 제출본이 모두 같은 목차를 참조한다.

## 관리자 화면

`/admin/navigation`에 목차 관리 화면을 추가한다. 모든 변경 요청은 로그인과 CSRF 검사를 거친 POST 요청으로 처리한다.

화면은 상위 메뉴별 카드 안에 메뉴 수정 폼과 하위 항목 목록을 보여준다. 각 항목에는 수정, 위로, 아래로, 삭제 동작을 제공하고 카드 아래에 하위 항목 추가 폼을 둔다. 화면 끝에는 상위 메뉴 추가 폼을 둔다. 삭제 버튼은 확인 문구를 표시하며, 서버의 기록 존재 검사 결과가 최종 기준이다.

홈과 사이드바에는 로그인한 사용자에게만 `목차 편집` 링크를 표시한다. 일반 방문자와 정적 제출본에는 관리 링크나 폼을 포함하지 않는다.

## 오류 처리

잘못된 ID, 빈 제목, 길이 초과, 허용하지 않은 아이콘, 개수 제한 초과는 `422`와 한국어 안내로 응답한다. 존재하지 않는 메뉴나 항목은 `404`로 응답한다. 연결된 기록 때문에 삭제할 수 없는 경우 `422`로 응답하며 먼저 기록을 이동하거나 삭제하라고 안내한다.

이동할 수 없는 첫 항목의 위로 이동과 마지막 항목의 아래로 이동은 상태를 바꾸지 않고 관리 화면으로 돌아간다. 홈 삭제 요청은 `422`로 거절한다.

## 정적 제출본

공개 스냅샷에 프로필, 공개 기록, 공개 첨부파일과 함께 목차를 포함한다. 내보내기는 스냅샷의 목차 순서대로 페이지를 만들고 홈의 둘러보기와 모든 사이드바 링크에 같은 제목과 순서를 사용한다. 공개 기록만 포함하는 기존 보안 조건과 64 MiB 제한은 유지한다.

## 테스트 기준

- 기존 저장소가 기본 목차와 기존 URL을 그대로 제공한다.
- 상위 메뉴와 하위 항목의 추가, 수정, 순서 이동 결과가 새 저장소 인스턴스에서도 유지된다.
- 이름 변경 뒤에도 기존 기록과 URL이 유지된다.
- 기록이 연결된 상위 메뉴와 하위 항목의 삭제가 차단된다.
- 빈 메뉴와 항목은 삭제되고 홈 삭제는 차단된다.
- 잘못된 입력, 잘못된 부모·자식 조합과 개수 제한이 거절된다.
- 목차 관리 화면과 모든 변경 요청은 로그인을 요구하며 POST 요청은 CSRF 검사를 요구한다.
- 공개 화면에 저장된 제목과 순서가 표시되고 관리 링크는 로그인 사용자에게만 보인다.
- 정적 제출본에 사용자 목차와 동적 페이지 파일이 포함되며 관리자 경로와 비공개 기록은 포함되지 않는다.
- 기존 전체 테스트가 계속 통과한다.

## 운영 제약

목차도 기존 기록과 마찬가지로 `storage/portfolio.pstore`에 저장된다. 무료 Render에서 재시작이나 재배포로 로컬 저장소가 초기화되면 편집한 목차도 사라질 수 있으므로, 제출 전 정적 ZIP과 `storage/` 백업이 필요하다는 기존 안내를 유지한다.
